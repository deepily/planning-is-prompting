## 2. Scope — four fixes, in dependency order

- **F1 — close the CREATE hole.** Refuse a raw `Write` to a non-existent record path; the denial names `memento_io.py write` (which already picks every path itself and cannot overwrite). Drops `memento_record_guard.py:139`.
- **F2 — guard `rm` of a live record.** Add `Bash` to the hook matcher; parse the command for `rm` targeting a RECORD path; refuse, and name the safe verb. Fails open on anything it can't parse (the file's existing stated posture — keep it).
- **F3 — kill the promotional surface.** Rewrite `memento_io.py:744-747` so exit 3 recommends `amend`, never "by hand."
- **F4 — make the backup a precondition, not a habit.** The documented repair recipe is `cp` → build → `rm` → `write`, and the `cp` is load-bearing with nothing enforcing it. Add a `memento_io.py repair` verb that does backup→verify-non-empty→replace→re-mirror→re-point as ONE call that fails loud, so the destructive step is never hand-typed.

**Out of scope**: the record/pointer split itself, the mirror design, `worktree_creation_guard.py`.

## 3. Acceptance criteria (all must be receipted, no self-report)

1. Raw `Write` to a NEW record path is refused (exit 2), stderr names `memento_io.py write`.
2. `memento_io.py write` to a NEW record path still succeeds — F1 must not break the sanctioned path.
3. `rm` of a live record via Bash is refused; `rm` of a non-record file is untouched.
4. `Write`/`Edit` on an existing record still refused (no regression on the one path that worked).
5. `memento_io.py write` against an existing record exits 3 with a message containing **no** "by hand" recommendation.
6. `repair` verb: refuses to proceed when the backup is absent or zero-length.
7. **Negative control**: the guard allows an ordinary `Write` to an unrelated `.md`. A guard that blocks everything is an outage.
8. Verification is by **sha256 on both sides + pointer read-back**, never by the script's own success report — that report is exactly what lied in the founding incident.
