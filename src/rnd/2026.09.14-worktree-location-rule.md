## Short answer

**Yes, we have that policy, and two things route around it.** The sanctioned place is `lupin/.claude/worktrees/`: it is gitignored, hidden, and swept by the arbiter janitor. But the seat spawner (since 2026-09-03) and hand-typed `git worktree add` commands both build **next to** the repo, where the janitor never looks and nothing ever removes them. The guard that was meant to catch the second case was built in July and **never installed**.

## The three leaks

### Leak 1 — the seat spawner builds next to the repo, and never reaps

`lupin/src/scripts/provision-seat-worktree.sh:113`:

```bash
TARGET="$( dirname "$MAIN" )/${REPO_NAME}-wt-${SLUG}"
```

The script says so itself (line 28): *"it never removes a worktree. Reaping is a separate policy … designed on row 9d654899, unbuilt."* So every spawned seat leaves a permanent tree next to the repo. Called from `lupin/src/lupin_mcp/session_spawner.py` (`provision_seat_worktree`, per seat).

### Leak 2 — hand-typed `git worktree add ../lupin-wt-<me>-<task>`

182 of 227. Nothing tells a worker where to put one: `lupin/CLAUDE.md:678` covers worktree **artifacts**, not **location**, and the persona-named siblings copy the spawner's naming.

### Leak 3 — the creation guard shipped inert and uninstalled

`planning-is-prompting/workflow/scripts/worktree_creation_guard.py` (ruled 2026-07-14, design `src/rnd/2026.07.14-worktree-lifecycle-policy-enforcement.md`). It is `MODE = "LOG_ONLY"`, is not in any `settings.json`, and its audit log does not exist, so it has never run. Both of its gates were Rick's, and neither was ever taken up.

## Proposed rule (for Rick to rule on)

**One place, one reaper: every lupin worktree lives under `lupin/.claude/worktrees/`, and a tree is removed when its seat is.**

| # | Change | Where | Recommendation |
|---|---|---|---|
| R1 | Spawner target becomes `<MAIN>/.claude/worktrees/seat-<slug>` | `provision-seat-worktree.sh:113` + its tests | **Adopt.** It is out of sight, already gitignored and already swept by the janitor, with no new root to maintain |
| R2 | Reap on dismiss: when a seat is dismissed, commit any WIP to a `seat/<slug>` branch, then `git worktree remove` (the June no-push, keep-the-branch rule) | `dismiss_sessions` path | **Adopt.** A seat's tree should not outlive its seat |
| R3 | One line in `lupin/CLAUDE.md` next to line 678: hand-made worktrees go under `.claude/worktrees/<persona>-<task>`, never `../` | `lupin/CLAUDE.md` | **Adopt.** Cheap, and it is where workers look |
| R4 | Install the creation guard, log-only first, so we can count the siblings still being made | `~/.claude/settings.json` (Rick's hand, per the July ruling) | **Adopt log-only now**; decide enforcement after a week of the audit log |

**Alternative to R1**: a hidden base next to the repo (`projects/.worktrees/lupin/<slug>`). It is equally out of sight and keeps trees outside the main checkout, but the janitor would need a second root and the docker mount `./.claude/worktrees` would not cover it. **Not recommended.**

## Risks to check before building

1. **The janitor's 6h idle rule inside the seat lane.** A live seat that sits idle for 6h would have its tree drained and removed under it. R1 needs the janitor to skip trees whose seat is alive (or a seat-lane exemption). **Must be settled before R1 lands.**
2. **Nested trees and repo-wide tools.** `grep -r` / `rg` run from the main checkout would descend into `.claude/worktrees/`. `rg` respects `.gitignore`; plain `grep -r` does not. This already applies today to the 6 TFE trees.
3. **`memento_repo_root` / reap_memento** collapse a worktree to its main checkout (`reap_memento.py:254-300`). The path change must not break that; its tests cover it.
4. **R2's WIP commit misses gitignored content** (Mr. Radio, from his census). The existing trees hold ~100 `.claude-memento-*.md` files plus `io/` data, all ignored. A reap must salvage ignored files it did not provision, not just commit tracked WIP.
   **Measured 2026-09-14 ~13:05 (María)**: a throwaway worktree holding only an ignored `.claude-memento.md` showed `status --porcelain` = 0 lines; a plain `git worktree remove` (no `--force`) exited 0 and **deleted the memento**. The probe tree is gone (`git worktree list | grep -c probe2` → 0). So the existing `drain_then_remove` already loses ignored files today, in every TFE/BFE and janitor reap. That is not specific to R1.
5. **A nested path starts with the main root** (Mr. Radio). Anything that prefix-matches a path against the project root, or keys off the directory name, can mistake a seat tree for the main checkout. Check `lupin/src/cosa/utils/util.py` (~line 700), `hook_credentials`, and `session_bridge` before R1 lands. Not yet verified by me.
6. **Two tools go blind** (Mr. Radio): `disk-hygiene-report.sh` and `stale-seat-scan.py` glob `lupin-wt-*`. They must learn the new lane in the same change.

**Sanity check**: Mr. Radio, 2026-09-14 12:50 EDT — *"R1-R4 hold, and Risk 1 is the right blocker."* Risks 4–6 are his.

## Build plan (Rick ruled R1–R3 + R4 log-only; voice order "as soon as possible")

**R2 changes shape: the janitor does the reap, and `dismiss_sessions` is not touched.** The dismiss path already relies on *"the worktree janitor provably keeps it"* (`session_spawner.py:1573`, `:1699-1702`), so moving seat trees into the janitor's lane gives them a reaper. What is left is to stop it reaping **live** seats, and to stop it losing ignored files.

**Mr. Radio's review of the build plan (13:06 EDT), all adopted:**
- **B4 changes: refuse, don't dump.** A salvage folder, even one just for mementos, is the pile moved somewhere nobody reads (Mr. Radio, 13:07). So **any ignored file that is not a build artifact refuses the removal**, mementos included (`skipped_reason="ignored_files_present"`, with the first files named in the result). Symlinks and the artifact skip-list never block. This should be rare: `memento_io` already writes a worktree seat's memento to the main checkout (`memento_repo_root.py:16`: 623 records in main, 0 in the worktree).
- **B3 gets a second liveness signal**: any live process whose cwd (`/proc/*/cwd`) is inside the tree counts as alive, whatever tmux says.
- **B3 re-locks on failure**: if the drain or remove fails after an unlock, the tree is locked again with its original reason.

**Risk 6 turned out moot, verified by reading and by existing tests**: `stale-seat-scan.py` enumerates with `git worktree list` (not a glob), sorts roots longest-first, and matches cwds by path component. `test_a_cwd_below_a_worktree_is_attributed_to_the_longest_matching_root` already covers a nested tree. `disk-hygiene-report.sh` counts via `git worktree list` and already reports `.claude/worktrees` bytes as "in-repo". Its `lupin-wt-*` glob now only catches hand-made strays, which is still worth counting. No change.

**Where I build**: my own tree at `lupin/.claude/worktrees/maria-worktree-rule`, locked, so the change itself follows the rule. **No `npm run build`** — this change touches no served bundle.

**Left open, named**: a seat killed outside tmux with its tmux session somehow still alive keeps its tree until that session dies. `stale-seat-scan.py` remains the backstop.
