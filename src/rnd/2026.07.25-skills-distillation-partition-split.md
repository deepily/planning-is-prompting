## The persona-edge finding (survives this partition)

⚠️ **The persona arm of the dangling-blocker class has no oracle even in principle today**,
because a bare persona name resolves against nothing. Worse than a dead reference: an overflow
name like `extra 1` is **re-granted after a reap**, so an edge may already point at a different
session. A dead ref waits forever; a recycled ref waits on the wrong person.

**The remedy is already on the board.** `91067e47` argues that ownership references should
stamp **session_id** alongside the name. The data exists — `get_session_info()` returns persona
and session_id together and every seat calls it at boot — so `6f8fd858` is an **exposure** gap,
not a data gap: the roster does not need to be collected, it needs to be surfaced.

**Sequence: stamp now, expose next, check last.** An unstamped edge written today is permanently
unrecoverable by any later instrument; a stamped one becomes checkable the moment the roster
lands. That asymmetry is why stamping should not wait for the checker.

*Why drop beats delete*: **absent reads as unresolved; dropped reads as dead. Only one of those
is a finding.**
