## 0. The problem, stated at its actual size

`verify` was never missing. It existed, scanned every slot, and exits 1. Run by hand on 2026-07-21 it
reported 28 findings on lupin. The eight days of mirror staleness were not a blind instrument —

> **they were an instrument nobody calls.**

A checker that is correct, complete, and never invoked is indistinguishable from one that does not
exist — and is worse, because *its existence reads as coverage*. `deddd1b` gave it a vocabulary.
This design gives it a caller, and then asks the harder question: what makes the caller stay.

**Corpus state after the cleared remediation** (`migrate --apply`, this session):

| | before | after |
|---|---|---|
| records / pointers | 238 / 8 | 242 / 8 |
| mirrored | 217/238 | **242/242** |
| UNMIRRORED | 18 | **0** |
| DRIFTED | 3 | **0** |
| BARE-SLOT | 7 | **7** |
| findings | 28 | **7** |

**The eight-day hazard is closed, and the claim needs stating precisely because it is easy to
overclaim**: the seven paths remain overwritable, but their content is now immutably twinned and fully
mirrored, so **an overwrite would no longer lose anything.** That was the hazard. The remaining
bareness is an untidiness with a known cost of zero — and it is what the caller must be designed
against, not the 28.

## 1. Q1 — what does a seat DO with N problems at boot?

**Answer: a seat is shown ONE line about ONE slot — its own — and it is never fatal.**

The instinct is to argue severity (fatal / warning / logged). That is the wrong axis, and every point
on it still produces a wall. The right axis is **audience**:

> **Scope the alarm to the actor who can afford the remedy.**

This is not a noise argument, it is an affordability argument, and the corpus proves it. Clearing a
BARE-SLOT requires `write --slot io --persona <p> --session-id <sid>` — measured this session:
`migrate --apply` does not clear it (it twins, never removes), and `regenerate-pointer` **refuses**
(`no record found` — a `-legacy-<date>` twin is not a session-id'd record). **The remedy needs a
session id that no heuristic can supply.**

Exactly one actor holds that id for a given slot: **the seat sitting in it.**

⇒ A corpus-wide wall shown to a seat lists 6 findings it *cannot* act on and 1 it can. A seat-scoped
line lists only the one it can. Same checker, same data — and the difference between an alarm and a
nag is entirely which rows the reader is able to close.

**Severity: never fatal, and this is not timidity.** A SessionStart hook that blocks a boot trades a
data-integrity nag for an outage. The guard file next door already states the principle for its own
domain — *"a guard that blocks everything is not a guard, it is an outage"* — and the memento system's
whole purpose is continuity across a re-spin. Refusing to start the successor in order to complain
about the predecessor's record inverts the point of the artifact.

**Clean output is printed, not suppressed.** One line either way. `a18bfec9` established that "all
consistent" and "the checker scanned nothing" must not look identical; a hook that prints only on
failure re-introduces that ambiguity at the boot surface, where the reader has the least context to
notice a silence.

```
memento: slot OK — io/mementos/tiffany.md -> tiffany-8113db4a.md, mirror matches

memento: BARE-SLOT — io/mementos/tiffany.md holds RECORD content at a POINTER path.
         Content is twinned + mirrored, so nothing is at risk. Clear it with:
           memento_io.py write --slot io --persona tiffany --session-id 8113db4a
```

The second form is a nag that is **one paste from closed, by the only actor who can close it.**

## 2. Q2 — whose problems? Two callers, two scopes, deliberately

| | **SessionStart hook** | **Manager-tick** |
|---|---|---|
| scope | this seat's slot only | whole corpus |
| audience | the seat | the manager |
| output | one line | full classified report |
| exit semantics | **always 0** (fail-open) | meaningful (0 / 1 / 4) |
| cadence | every boot | per tick |
| can act? | yes — holds the session id | yes — owns the board, can mint rows |

These are not two severities of one alarm; they are two questions. *"Is MY record safe?"* is closable
by a seat in one command. *"Is the CORPUS healthy?"* is a board question — the 7 residual bare slots
include four belonging to dead or overflow personas whose session ids **nobody can legitimately
supply**. Those need a ruling, not a nag, and a ruling is the manager's surface.

⚠️ **The overflow-persona slots are their own hazard**, and the reason seat-scoping must key on the
*resolved* persona name rather than a guess: per saved memory, overflow names (`extra N`, `arnold`) are
**re-granted after a reap**, so a future seat can inherit a slot whose record belongs to someone else.
A seat-scoped check that says "your slot is fine" about a predecessor's record would be a confident
wrong answer. The line therefore names the record it checked, rather than returning a bare verdict.

## 3. Q3 — the anti-flip guard (the hard question)

> *"If someone later disables the call, what fails? A caller that can be silently removed reproduces
> the original defect with extra steps."*

**I cannot make a hook un-removable, and I will not pretend otherwise.** It lives in
`~/.claude/settings.json` — user-scope, outside every repo, invisible to every suite, one edit from
gone. Any design that answers this question with "add the hook and be careful" has answered it with a
rule, and a rule does not act.

**So the assertion moves out of configuration and into code that is already tested and already run.**

**Mechanism — the staleness receipt:**

1. `verify` writes a receipt on every run: `~/.claude/mementos/<repo>/.last-verified` — out-of-repo,
   beside the mirror it audits, never in the tree.
2. `memento_io.py write` — the verb **every seat runs at every re-spin** — reads that receipt and, when
   it is missing or older than the threshold, prints a banner *before* doing its work:

   ```
   !!! NO VERIFY HAS RUN AGAINST THIS REPO IN 9 DAYS (or ever).
       The mirror-divergence checker is not being called. Findings accumulate unseen.
       Run: memento_io.py verify --repo <repo>
   ```

**Why this is a mechanism and not another rule:** the caller's *absence* now produces a signal at the
moment of highest attention, through a path that does not depend on the caller existing. Deleting the
SessionStart hook does not buy silence — it buys a banner on the next memento write, i.e. within one
re-spin rather than within eight days.

**And the check itself is under test.** Removing the staleness warning means editing `memento_io.py`,
which is guarded by 186 tests, one of which will assert the banner fires on a missing or stale receipt.
That is the whole trick:

> **Move the liveness assertion from a file no test can see into a file every test runs.**

**Its honest limit, stated rather than buried:** a determined edit can still remove both. This design
does not claim tamper-proofing. It claims that *silent decay* — the failure that actually happened —
becomes loud, and that the remaining removal path is one a test will redden.

**Threshold**: 72h proposed — long enough that a quiet weekend does not cry wolf, short enough that
eight days is impossible. Open for a ruling (§6).

## 4. Q4 — blast radius

A SessionStart hook runs for **every seat on every boot**, and per Rio today, **hooks execute from the
working tree** — a change is live on the next fire, with no deploy. That cuts both ways: fast to fix,
and fast to break for everyone at once.

**Measured, not asserted:**

| | |
|---|---|
| full-corpus `verify` on lupin (250 memento files) | **50 ms**, stable across 5 runs |
| seat-scoped check (one slot, one mirror stat, one sha) | strictly less — no directory walk |
| writes performed by `verify` | **zero** — read-only by contract, pinned by `test_verify_writes_nothing` |

50 ms for the *whole corpus* is already inside the noise of a boot that shells out to `git rev-parse`.
The seat-scoped path is cheaper still. **Cost is not the risk here — behaviour is.**

**Failure modes the hook must survive, all fail-open (exit 0, say why, continue):**

| condition | behaviour |
|---|---|
| `PLANNING_IS_PROMPTING_ROOT` unset / script missing | silent exit 0 — a seat in a repo without the tooling is not broken |
| persona unresolved (`voice_persona is None`) | print "slot unknown, skipped" and exit 0 — **never guess a slot** |
| repo has no `io/mementos/` | silent exit 0 — not every repo participates |
| any exception | exit 0, one diagnostic line |

**The one behaviour that must NOT be fail-open** is the "slot unknown" case wearing a clean result's
face. It prints *skipped*, never *OK* — the same rule as exit 4: an unscanned thing must never look
like a scanned one.

## 5. Item 2 — the pointer-path deny (brought WITH the design, per the row)

**The hole**, `memento_record_guard.py:570`:

```python
if not is_record_path( abs_path ): return 0   # a CANONICAL pointer: ALLOW, always
```

`io/mementos/<persona>.md` **is** a pointer path, so a hand-write of RECORD content there is allowed
**by name**. That is the door this defect walked through.

**The allowance cannot simply be dropped** — measured, not assumed: Layer 2 rewrites the pointer on
**every** memento write, so a blanket refusal breaks `memento_io` itself.

**Proposed narrow deny.** Refuse a pointer-path write only when **all three** hold:

1. the target path exists, **and**
2. the file currently there is **NOT** a pointer (first line lacks `POINTER_MARK`), **and**
3. it has **no byte-identical mirror** out-of-repo.

⇒ **Deny only the overwrite that would destroy the last copy of something.**

**Why each condition is load-bearing:**

- **(1)** a pointer write onto nothing destroys nothing.
- **(2)** overwriting a real pointer destroys nothing — the entire premise of the record/pointer split,
  and Layer 2 depends on it. This condition is what keeps the guard from becoming an outage.
- **(3)** is what makes this a *loss* guard rather than a *style* guard. Once the content is mirrored,
  the overwrite is recoverable and the write should proceed. **This matters right now**: all 7 lupin
  bare slots are mirrored as of this session's remediation, so the deny would fire on **none of them**.
  It guards the next unmirrored one, not the existing residue.

**Denial text must name the recoverable path** in that file's established voice: what the file at that
path actually is, that it has no mirror, and the exact `write --slot io` invocation that lands the
content properly instead.

**⚠️ One thing I could not verify and am not claiming.** The wiring is `"matcher": "Write|Edit"`, while
the guard's own `MUTATING_TOOLS` is `{Write, Edit, MultiEdit}`. If the matcher is an unanchored regex,
`MultiEdit` matches through its `Edit` substring and the code is reachable; if it is anchored or exact,
**the guard defends a door the wiring never opens.** I did not find the harness's matcher semantics
documented and would not assert either way — this is a *question*, not a finding. **It should be
answered before the deny ships**, because a deny unreachable by one of the three mutating tools is
coverage on paper. Cheap check: one `MultiEdit` against a guarded path, observed.

## 7. Rejected, with reasons

| rejected | why |
|---|---|
| Corpus-wide report at every seat's boot | 7 findings × every seat × every boot, 6 of 7 unactionable by that reader. An alarm that is always on teaches its reader to skip alarms. |
| Fatal SessionStart on findings | Trades a data nag for an outage; inverts the purpose of a continuity artifact. |
| Hook-only, no staleness receipt | The hook is the thing that can be silently removed. Answering "what if the caller disappears" with another caller is the original defect with extra steps. |
| Auto-repair at boot | Mutating a shared tree from a hook, unattended, on every seat's boot — and the repair needs a session id no heuristic can supply. The settled AC-2 ruling, now load-bearing twice. |
| Blanket deny on pointer-path writes | Measured to break Layer 2, which rewrites the pointer on every write. |
| Asserting the settings.json hook entry in a test | The file is user-scope and outside every repo. A test that cannot see its subject is decoration. |
