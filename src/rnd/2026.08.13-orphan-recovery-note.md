# Orphan recovery note — live seats and where their continuity lives, 2026-08-13 12:17 EDT

**Why this file exists.** `workflow/manager-context-monitoring.md` §4c says that when a spawning
manager goes dark, its workers' seats are orphaned: no peer can reap, respawn, or re-spin them,
because `dismiss_sessions` reaches only sessions the caller spawned. The only remaining actor is a
human at a terminal — **and a human can only act on a seat whose name somebody wrote down.**

Two managers were over budget and climbing ~5 points per quarter hour when this was taken. Both
answered while they still could. **This is the window closing, captured.** Everything below is
quoted from their own `list_spawned_sessions()` reads, not from memory or from my inference.

## The finding that came out of asking

**Mr Radio's cron `5706ab73` is session-only too.** I could not verify it earlier — the user crontab
is empty and the hash is not in lupin — and the reason is that it was created with the harness's
in-session scheduler, exactly like mine. **So neither manager's timer survives its session**, which
is the precise failure §1b was written about, holding for both people who wrote §1b.

**Owed to the next person in either seat**: install
`workflow/scripts/context-pressure-tick.sh` in a real crontab. Until somebody does, every timer in
this fleet dies with the session that made it.
