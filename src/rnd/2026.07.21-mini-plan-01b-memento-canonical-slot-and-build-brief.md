## 1. F5 — the defect, derived at source today

`af0c5700` (filed by María from the `task_edit` post-game): Krishna's crew memento reported **written** and was
**absent at the canonical slot**. A slug-pattern write matched the NEAREST `io/mementos/` — a real sibling dir —
not the canonical repo-root one. No error. No mirror. No pointer.

Re-derived on disk today, 2026-07-21:

```
$ find . -type d -name mementos
./io/mementos                    <- canonical (repo root)
./src/lupin-mobile/io/mementos   <- legitimate: separate git repo, its own toplevel
./src/cosa/rest/io/mementos      <- ⚠️ STRAY, EMPTY, UNTRACKED, created 2026-07-20 22:03
```

The stray dir is still on disk. `git ls-files src/cosa/rest/io/` returns nothing — it was never tracked; the
record was moved to the canonical slot by hand after the landed-verify caught it.

**Root cause is NOT `memento_io.py`.** That script resolves its target via `find_repo_root()` →
`git rev-parse --show-toplevel` (`memento_io.py:260-278`) and is immune. The misdirect came through the
**bypass path** — a raw `Write` to the *relative* doctrine path `io/mementos/<slug>.md` from a session whose
cwd was a subdirectory. The `Write` tool creates parent dirs, so it succeeded, silently, at the wrong target.

⇒ **F5 belongs in exactly the same file as F1/F2**: `memento_record_guard.py`, the PreToolUse hook that is the
only thing acting on the never-invoked-the-script path.

## 2. F5 — the fix

Add a canonical-slot check to `memento_record_guard.py`, applied to **any** Write/Edit whose path names a
memento (RECORD **or** POINTER, io-slot **or** root-slot):

- **io-slot**: the `io/mementos` segment MUST sit directly at the git toplevel of the target path.
- **root-slot** (`.claude-memento*.md`): the file MUST sit directly at the git toplevel.
- Resolve the toplevel by running `git rev-parse --show-toplevel` from the **nearest existing ancestor** of the
  target (the target itself will not exist on a create).
- **Not inside a git tree ⇒ ALLOW.** Fail open, matching this file's stated posture. A guard that blocks what it
  does not understand is an outage.
- Denial names the canonical path it should have been, verbatim, so the fix is copy-pasteable.

**Why this catches `af0c5700` and F1 does not**: F1 refuses a raw `Write` that CREATES a record. A *pointer*
write (`io/mementos/<persona>.md`, no session-id suffix) is deliberately always allowed by F1 — and a
misdirected pointer is exactly as invisible as a misdirected record. F5 is orthogonal to F1: F1 asks *"is this
the sanctioned verb?"*, F5 asks *"is this the sanctioned place?"*

**Worktrees stay legal by construction**: a worktree's `git rev-parse --show-toplevel` returns the worktree
root, so `<worktree>/io/mementos/` passes. `src/lupin-mobile/io/mementos/` also passes — it is a separate repo
whose toplevel is `src/lupin-mobile`. Neither needs a special case; the check is *relative to the target's own
repo*, never to any one repo.

## 3. F5 acceptance criteria

All receipted, no self-report. Numbering continues María's §3 (1–8).

9.  A `Write` to `<repo>/src/cosa/rest/io/mementos/foo-abcd1234.md` is **refused** (exit 2); stderr names
    `<repo>/io/mementos/foo-abcd1234.md` as the canonical path.
10. A `Write` to `<repo>/io/mementos/foo-abcd1234.md` is **allowed** — F5 must not break the canonical create.
11. A **POINTER** write to a non-canonical dir (`<sub>/io/mementos/persona.md`) is **refused**. This is the case
    F1 cannot see.
12. A pointer write to the canonical dir is **allowed** (Layer 2 rewrites the pointer on every write — blocking
    it breaks the mechanism).
13. A memento path inside a **git worktree** whose `io/mementos` is at the worktree root is **allowed**.
14. A memento path in a **nested separate repo** (`src/lupin-mobile/io/mementos/x-abcd1234.md`) is **allowed** —
    its own toplevel is `src/lupin-mobile`.
15. A memento-shaped path **outside any git tree** is **allowed** (fail-open control).
16. **Negative control**: an ordinary `Write` to an unrelated `.md` anywhere is untouched.
17. **The stray dir is removed**: `src/cosa/rest/io/` is gone from the Lupin tree, verified empty first
    (`find src/cosa/rest/io -type f` returns nothing) before any `rm`.

## 5. Risk

Low, fully reversible — one hook file, one script, one empty directory. The one real hazard is **F5 refusing a
legitimate write we have not thought of**; AC-10/12/13/14/15 exist solely to catch that and are hard merge gates.
A second hazard is subtler: `git rev-parse` is a **subprocess in a PreToolUse hook**, so it is on the latency path
of every Write. Measure it; if it is not sub-10ms, gate the subprocess behind the cheap regex (only run git when
the path already looks like a memento) — which the design does anyway.
