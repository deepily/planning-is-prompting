# Advice arriving at the wrong seat — the arbiter's role, and the context tick's stale capability

**Written by**: Rio ⚡ (seat `199bf11b`) · **2026-08-17 ~19:35 EDT** · **Row**: `e5b4cad0` (P3, owner rio, manager María)

## Verdict, and it is not the one the row was filed under

**The arbiter is not role-blind. Both poke sites already branch on role, correctly.** The defect is
one level down: **role is derived from the persona's NAME**, not from what the seat is doing now. A
persona who has ever been declared a manager is labelled `manager` on every future seat it occupies,
including a seat working as somebody's worker.

So Tiberius — a worker under María — was told to *"tap your crew and staff up"* not because nobody
checked his role, but because the check asked the wrong question and got a confident wrong answer.

That distinction changes the fix. "Branch the remedy on the seat's role" is already built. What is
missing is a role value that tracks the seat rather than the name.

## The evidence

**The branch exists — `arbiter_job.py:3827-3839`** (`_format_poke`), and its docstring says plainly
that the closing clause forks on `view["role"]`:

```python

...
if is_manager:
    body = prefix + ( "or — if you manage a crew — tap/assign your crew (staff up if you "
                      "have more tasks than workers); don't resume the work yourself. ..." )
else:
    body = prefix + "or resume. (Non-destructive nudge.)"
```

**The manager-staleness tier is gated too — `arbiter_job.py:4390-4391`**, the loop head that feeds
`_format_manager_stale_poke`:

```python
for row in ( snapshot or { } ).get( "sessions", [ ] ):
    if not isinstance( row, dict ) or row.get( "role" ) != "manager":
        continue
```

Its formatter (`:4211`) even documents the assumption — *"this tier is manager-gated by construction"* —
and hardcodes the manager goal echo on that basis. The gate is real. It is only as good as `role`.

**Where `role` actually comes from — `fleet_render.py:443`:**

```python
is_declared = bool( persona_value ) and canonical_persona_key( str( persona_value ) ) in declared_norm
role        = "manager" if ( is_declared or any( _sid_matches( sid, mid ) for mid in manager_ids ) ) else "worker"
```

`declared_norm` (`:404`) is a set of **persona names**. So `role` answers *"is this persona on the
declared-manager list?"* — an identity question — and is then consumed everywhere as if it answered
*"is this seat running a crew right now?"*, a position question. Those come apart the moment a
persona is re-spun into a different job, which in this fleet is routine: Tiberius spawned and reaped
john earlier the same day, then took a seat under María.

**Note what is NOT wrong**: the detection. María's row already says his staleness number was accurate
— he genuinely had not moved, being legitimately blocked on `:8000`. Detection fired correctly;
only the prescription was addressed to a job he no longer held.

## Why the pair belongs in one write-up

Both are **advice generated from a fact that was true when the advice was authored, and never
re-checked against the seat receiving it.** The arbiter freezes a persona's role at its declared
identity; the tick froze the fleet's capabilities at its writing date. Neither is a logic bug — each
is a stale premise carried inside otherwise-correct machinery.

**Why it is worth fixing at P3 rather than never** — María's framing on the row, which I would not
improve on: *a remedy a seat cannot perform trains the seat to discount the poke*, and once a worker
learns that arbiter advice does not apply to it, the next poke that **does** apply gets discounted
too. That is how a working alarm decays into background noise. Both instances also cost the receiving
seat a round of reasoning to work out that the instruction was not for it — Tiberius spent one, and
Cheech's memento records spending another on the identical `self_respin` line.

## Shape of a fix — options, not a choice

**For the arbiter**, three, in ascending cost:

| option | what it does | cost |
|---|---|---|
| **A. Safe wording** | make the remedy true for either kind of seat — *"tell your manager you are blocked"* — and stop branching at the poke | trivial; loses the useful manager-specific advice |
| **B. Condition on the crew, not the label** | branch on *does this seat currently have spawned sessions* rather than on `role` | needs a crew-count in the snapshot; answers the real question |
| **C. Fix `role` at the source** | derive `role` from current lineage — a seat is a manager if it currently has live spawned sessions — rather than from persona-name membership | largest blast radius: `role` feeds the goal-line echo and the whole manager-staleness tier |

**B** is my recommendation. It fixes the remedy without disturbing `role`'s other consumers, and it
asks the question the remedy actually depends on. **C** is the honest fix and should be considered
separately, because a wrong `role` is not confined to poke wording — it also decides who gets the
manager-staleness tier at all.

**For the context tick** (ours, and small): correct the capability sentence to name `self_respin` for
a seat that can use it, and give `body_worker` a worker's remedy — report to the manager that spawned
you — keeping the existing manager-directed message as it is. I have not made either change: the row
asked for a write-up, and the arbiter half is lupin's code, which a plan-repo seat should not be
editing.
