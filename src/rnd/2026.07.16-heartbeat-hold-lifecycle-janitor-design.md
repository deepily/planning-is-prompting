## 1. ANSWERING RICK'S QUESTION: what IS `ttl_seconds`?

**It is not a filesystem mechanism.** There is no OS-level expiry, no tmpfs, no systemd timer, no
`O_TMPFILE`. It is a plain integer field in the hold JSON. It is **advisory data** consulted by
exactly two readers:

| Reader | Question it answers | Receipt |
|---|---|---|
| `is_fresh( hold )` | "Should the Stop-hook honor this hold and decline to poke?" | `heartbeat_hold.py:502` |
| `prune_stale_hold_files()` | "Is this file provably old enough to delete?" | `heartbeat_hold.py:421` |

If neither reader runs against a file, the number is inert and **the file lives forever**. That is
the current state for 41 of 41 files outside lupin's root.

**Freshness is anchored on the file's host-real mtime, NOT `held_at`** (B1, bug `d44b7068`,
2026-06-27). Rationale, verbatim from the module: *"AGENTS HAVE NO RELIABLE WALL-CLOCK — a
JUST-WRITTEN hold could read stale and the session was re-poked forever despite a fresh hold. The
host's mtime cannot lie about when the agent last refreshed."* `held_at` is a fallback anchor only,
used when no mtime annotation is present.

## 4. FEATURE A — mechanically force deletion of dead/superseded holds

### A0. Root cause (one line)

`fleet_arbiter_loop.py:502` calls `self._hold_janitor_fn()` with **no `base_dir`** → resolves to
`LUPIN_ROOT` → the janitor is structurally blind to every non-lupin repo. **This is the identical
defect that `resolve_hold_base_dir` (facet 3) and `read_hold_resilient` (bug `1789f197`) were each
written to fix on the READ side.** The lesson was learned twice and never applied to the janitor.

### A1. Widen the janitor's sweep (the actual fix)

- `prune_stale_hold_files` gains a **multi-root sweep**: accept `base_dirs` (iterable) alongside the
  existing `base_dir`, preserving the current single-dir signature for every existing caller.
- The arbiter passes the **enumerated fleet roots**, not `LUPIN_ROOT`. Source of truth for the root
  list is a design question (§6 Q1) — do **not** invent a new registry without ruling it.
- Sweep must be **recursive within each root** (`rglob`), bounded by depth + a skip-list
  (`.venv`, `node_modules`, `.git`, `.claude/worktrees`). The `lupin/src/migrations/versions/`
  stray proves holds land wherever a session's cwd happened to be — a root-only glob misses them.

### A2. Make the 22 immortal files prunable — WITHOUT weakening the janitor

The janitor's conservatism is **correct and must not be relaxed**: "can't prove age → KEEP" is what
guarantees it never reaps a live session's hold. Do **not** "fix" this by deleting null-TTL files.

Instead, give it a **second, independent age proof** it already has access to:

- **When `ttl_seconds` is unusable, fall back to the file's host-real mtime** — the same B1 anchor
  `is_fresh` already trusts, and the same one whose docstring says *"the host's mtime cannot lie."*
  A file whose mtime is older than `DEFAULT_TTL_SECONDS + grace` is provably ancient regardless of
  what its JSON claims.
- This is strictly **more** conservative than the status quo in the only way that matters: it still
  never touches anything recently written, and it still honors `live_session_ids`.
- ⚠️ **NEGATIVE CONTROL REQUIRED (R-3, non-negotiable):** the crew must prove this prune can FAIL —
  plant a null-TTL hold with a *fresh* mtime and assert it **survives**, beside the assertion that
  an old one is reaped. An absence-assertion without a presence-assertion beside it is the exact
  defect class this whole week was made of. *"The check existing is not the check working."*

### A3. Close the bypass at the choke point (the R-1-shaped half)

Widening the sweep reclaims today's cruft. It does **not** stop agents hand-writing malformed holds
tomorrow — which is the actual generator.

- **Expose hold-writing as the only sanctioned path**, the way `memento_io.py` is the ruled path over
  a hand-`Write` for mementos. A CLI entry point (`heartbeat_hold.py write …`) mirroring
  `memento_io.py write` gives agents a mechanism to reach for and doctrine a verb that exists.
- Doctrine (global CLAUDE.md + `workflow/`) must then prescribe **that verb** — not a JSON shape.
  A documented JSON shape has been in force for days and is **0-for-23**. This is `74a3ff4d`'s
  remedy applied one layer down: *stop prescribing shapes; prescribe verbs that exist.*
- **Anti-scope note:** do NOT try to *forbid* the Write tool. The lever is making the mechanism
  cheaper than hand-rolling JSON, plus the janitor cleaning up after those who don't.

### A4. Explicitly OUT of scope

- **Do NOT strengthen the hold-writing prose.** (R-7's trap: the vivid failure is the malformed
  file; the load-bearing fix is the mechanism + the janitor. **Cost-order, never drama-order.**)
- **Do NOT relax the janitor's bias-to-keep.** A false prune reaps a live session's hold and
  restores the ping-storm this all exists to prevent.

## 5. FEATURE B — ignore coverage (forward guarantee, not cleanup)

Nothing is tracked today (§2). This feature is about the **next** repo, not this disk.

- Fold `.heartbeat-hold-*.json` into the **runtime-state family** already handled at install time
  (`.claude-session.md`, `.claude-memento.md`) — the module's own docstring already calls it a member
  of that family and asserts it is "gitignored." That assertion is currently **true by luck in 2 of
  2 git repos, and unenforced.**
- **Verification, not assertion**: `/plan-install-wizard` (or the janitor's own tick) asserts the
  pattern is ignored in every registered repo and reports the gap. A claim in a docstring that
  nobody checks is precisely the shape under audit here — *"a false claim in a docstring becomes the
  next reader's ground truth"* (Rachel).
- **Reference test**: `git check-ignore -q .heartbeat-hold-test.json` per registered repo — a real
  presence-assertion, machine-computed, not an eyeball.
