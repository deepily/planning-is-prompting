## 0. The ask

Rick, 2026-08-06, verbatim in substance:

> *"I'm sick and tired of stray heartbeat hook holds and mementos being left all over the file system. One of the problems with cleanup is that someone has to do it and yet no one is. If we're using a temp file on a server that gets turned off every night then we don't have to worry about cleanup because that is the nature of a file written as a temp file to the temp directory by Python on Linux."*

And on carryover, which is the part that makes this a workflow change and not just a path change:

> *"I have decided to start doing as a matter of procedure [that] the last couple hours of the day are dedicated solely to clearing the board such that no new bugs get written and all institutional memory of the day's events gets written to the history file. I literally want to start each new day fresh and do not want to carry temporary mementos overnight."*

Two things are being asked for, and only one of them is a code change:

1. **Code**: holds and mementos are written to host `/tmp` so the nightly boot wipe collects them.
2. **Workflow**: mementos stop being a durable record. The durable record becomes `history.md`, written during an end-of-day board-clearing window.

## 4. Design

### 4.1 Holds — small, clean, one choke point

`heartbeat_hold.py` funnels every path through `_resolve_base_dir()`. That stays the only place that knows.

```python
# heartbeat_hold.py
HOLD_DIR_ENV      = "LUPIN_HOLD_DIR"
HOLD_DIR_FALLBACK = "/tmp"
```

Resolution order: explicit `base_dir` argument (tests and explicit callers win — unchanged) → `$LUPIN_HOLD_DIR` → `/tmp`.

**Fall back, do not fail loud.** §4.2 of the prior doc specified fail-loud-when-unset and it was **overridden at implementation**, because a fail-loud resolver on this path is a fleet-wide outage. Honor that precedent; do not re-argue it.

Everything downstream follows for free: the hooks, the arbiter on `:8001`, `session_spawner.clear_hold`, and `follow_through_escalation_watcher`.

### 4.2 The bind-mount — required, and here is the one reader that requires it

`follow_through_escalation_watcher.py` globs `.heartbeat-hold-*.json` and **runs inside the REST container**. It already accepts a configurable `hold_base_dir` (line 110), so it is a parameter, not surgery — but it is the reason `/tmp` must be visible inside the container rather than being a host-only convention.

```yaml
# docker-compose.yml — lupin-rest-dev, lupin-rest-test
volumes:
  - /tmp:/tmp
```

⚠️ **Mounts resolve at container CREATE.** This needs `docker compose up -d --force-recreate`. A plain `restart` applies it silently-not-at-all.

### 4.3 Mementos — the larger change, and it is not symmetric with holds

`memento_io.py` is more opinionated than `heartbeat_hold.py`, and three of its invariants are repo-shaped:

- `record_rel_path( slot, persona, sid )` returns a **repo-relative** `Path`, and `raise ValueError` on any slot outside `{io, root}`.
- `find_repo_root()` exists specifically so a write lands in *the canonical slot*, not wherever the working tree happens to sit — a defect it was written to close.
- **`write --slot root` REFUSES when a crew ran and no post-game exists** (ruling R-1, gate closed 2026-07-21).

So a third slot is a contract change, not a new enum value. Two options:

| | Approach | Trade |
|---|---|---|
| **A** ✅ | Add `slot="tmp"` → absolute `/tmp/mementos/<repo>/<persona>-<sid>.md`, and relax the repo-relative return contract for that slot only | Keeps `io`/`root` intact for anything still wanting durability; the contract gets a documented exception |
| ~~**B**~~ ❌ | ~~Repoint the `root` slot's base directory via env var~~ | **DEAD — see below** |

### 🔴 APPROACH B IS DEAD. Mr Radio killed it on measurement, 2026-08-06.

I recommended B and was wrong about the blast radius. It does not merely need care — **it refuses to write at all**:

- **`memento_io.py:1131`** — `if not ensure_gitignored( repo_root, rec_rel ): <refuse>`. That runs `git check-ignore` on the path. Hand it an absolute `/tmp/...` and check-ignore returns non-zero, so **the write is refused before it starts.** One line, hard fail.
- **`authored_at:698`** — `path.relative_to( repo_root )` → **`ValueError`** on a `/tmp` path.
- **`mirror_path_for`** — `MIRROR_HOME / repo_root.name / rel_path`; an absolute `rel_path` **silently discards the mirror prefix**. It does not crash, which makes it the more dangerous of the two.
- **8+ sites** do `repo_root / pointer_rel_path(...)`, which "works" by accident with an absolute path.

⇒ **Approach A — the third slot.** It keeps every repo-relative helper honest instead of quietly feeding them absolute paths that three of them mishandle in three different ways. The smaller-diff argument for B was measuring the wrong thing: B's diff is small only until you count the four seams it breaks.

**Owner: me** (planning-is-prompting is my repo). Reclaimed 2026-08-06 — Mr Radio put the question to Rick and it timed out, and a timeout is not a ruling.

### ✅ RULED 2026-08-06 — the R-1 gate stays exactly where it is

The gate refuses `write --slot root` when a crew ran and no post-game exists. I originally recommended moving it onto the `history.md` write, reasoning that *"gating an ephemeral file protects nothing."*

**That reasoning was wrong, and I withdrew it before asking.** The gate was never protecting the memento file — it uses that write as a **tripwire at a specific moment**: the last instant before a session loses everything it knows. The file becoming ephemeral does not move the moment. Attaching it to the end-of-day history write sounds tidier but lands it too late — sessions are re-spun all day, and by evening the run that needed harvesting is hours gone.

Rick ruled: **leave it.** Zero code change; it keeps working through this migration untouched, which is a further point in favor of approach B over a third slot.

⚠️ **One thing owed**: a comment beside the gate explaining why a control guarding a throwaway file is deliberate. Without it, this reads as obvious dead weight and somebody removes it in six months.

### 4.4 The guardrail, stated because a future session will get it wrong

**Files in `/tmp` — never a worktree, never a session cwd in `/tmp`.**

This is the distinction Rick drew and it is exactly right: `detect_project()` walks up from cwd to the nearest `.git`; a *file* written to `/tmp` moves nobody's cwd. Write it into the hold/memento docstrings and into `workflow/` — the existing global config text warns against `/tmp` in terms broad enough to read as "never touch `/tmp`," which will now be wrong.

## 5. Phase 3 — the sweep, and why it needs its own decision

Rick chose to sweep the legacy backlog. Inventory:

| Slot | Files |
|---|---|
| Repo-root mementos | 42 |
| Mirror `~/.claude/mementos/` | 509 |
| `io/mementos/` | 391 |
| Orphaned `.heartbeat-hold-*.json` | 34 |
| **Total** | **976** |

Footprint is trivial (0.6 MB for the repo-root set). The reason to be careful is not size.

🔴 **The backup will not save you.** §5 of the prior doc measured this: `rsync-backup.sh:148-149` and `sync-to-backup.sh:69-70` both run `rsync -avh --delete`, with no `--backup`, no `--suffix`, no versioning. **It is a mirror, not an archive.** Delete a file here and the next backup run deletes DATA02's copy. The backup protects against losing the disk; it does not protect against deleting something you wanted.

⇒ **Sweeping 976 files is irreversible across both disks.**

### ✅ RULED 2026-08-06 — straight delete, no archive

Rick, asked with the mirror finding in hand, chose **3b — straight delete**:

> *"It is an incomplete view of what's been going on here. So no, I don't care — delete them. Do not want yet another archive sitting around waiting for someone to come back to it just in case. I'm done with them, let them go."*

Two reasons in that, and both hold:

1. **The corpus is partial anyway.** 976 files across four slots, written by whoever happened to be seated, with no guarantee any given run is represented. An archive of an incomplete record buys less than it looks like it buys.
2. **An archive is the same disease.** A tarball nobody opens, kept "just in case," is precisely the species of artifact this whole plan exists to stop accumulating. Preserving it would have contradicted the ask.

⇒ **Phase 3 is an unconditional delete of all 976.** No tarball, no staging directory, no "move to `.trash` first."

*(Superseded: this section previously recommended archive-then-delete, and said to place the tarball "outside the rsync tree" — which was also backwards, since inside the backed-up tree is what would have mirrored it to DATA02. Both moot now; recorded so the reasoning isn't re-derived.)*

**Ongoing expiry after the sweep**: the boot wipe handles `/tmp`. But `projects-data/lupin` (709 files) is *not* in `/tmp` and is not in scope for this plan — flagging it as the next instance of the same problem, not smuggling it in.
