## 2. Hole 1 — the gate is opt-in, and the default is off

`qualifies_for_post_game()` returns `(False, [])` unless `slot == "root"`. `io` is the **default**.

```
$ memento_io.py write --slot io --persona Rachel --session-id 48b59a71 --repo .
EXIT=0          # crew record present, NO retrospective anywhere on disk
```

Both polarities in the same bed: the identical state on `--slot root` exits 6.

This is **partly by design** — a reaped worker owes a retro *deposit* (memento element 9), not a
post-game; the harvest belongs to the seat that survives the engagement. What is *not* by design is
that the protection is one un-typed flag deep and **the un-typed direction is the ungated one**. A
seat that omits `--slot` is not gated, is told nothing, and has no way to notice.

Pinned by `test_UNRULED_slot_io_bypasses_the_gate_today`.

## 3. Hole 2 — the evidence does not travel, so the gate is weakest where it was built to fire

Arming depends on other seats' records in `io/mementos/`, which this script **deliberately keeps
gitignored** (`REQUIRED_IGNORES`). Gitignored files do not survive a clone or `git worktree add`.

```
crew records in the working repo      : 25
crew records in a fresh worktree      :  0     # same commit, one ordinary `git worktree add`
$ memento_io.py write --slot root ... (in the worktree)
EXIT=0          # gate never armed
```

**A crewed engagement is exactly when seats work in isolated trees**, and this repo has an active
worktree-lifecycle workstream. So the gate is disarmed precisely for the seats most likely to be
doing careful, isolated work.

This also **corrects the original blast-radius reading**: a re-cloning seat does not get a
permanently *satisfied* gate (evidence looking falsely fresh) — it gets a permanently *disarmed*
one (no evidence at all). Different mechanism, larger hole.

Pinned by `test_UNRULED_gitignored_crew_records_do_not_arm_a_fresh_worktree`.

## 4. Why these were carved out rather than patched

1. **They are rulings, not bugs.** Whether a worker's `io` write should be gated is a question about
   what the fleet owes, not about whether the code is correct. Patching it inside a bugfix would
   settle a policy question by implementation — the thing the review exists to prevent.
2. **Hole 2's obvious fix has real blast radius.** Un-gitignoring `io/mementos/` would put every
   seat's memento into git history permanently — a privacy and volume decision well above this script.
3. **Both are now pinned in code**, not only in prose. When a ruling lands, the `UNRULED_` tests go
   **red**, forcing whoever implements it to consciously delete a test rather than skim a docstring.

## 5. Options for ruling

### Hole 1 — should `--slot io` be gated?

| option | pros | cons |
|---|---|---|
| **A. Leave as-is (opt-in)** | Preserves the deliberate design: a worker owes a deposit, not a retro. No risk of blocking a re-spin. | Coverage depends on a flag nobody types. Silent. |
| **B. Gate `io` too** | Closes the hole completely. | Wrong by construction — a reaped worker genuinely does not owe a post-game. Would fire on every worker every time and train seats to reach for `--no-post-game` reflexively, degrading the escape hatch. |
| **C. Make the slot explicit — no default** ⭐ | Forces a conscious choice; the ungated direction stops being the silent one. Does not change what either slot *means*. | Breaks every invocation that omits `--slot`; a one-line fix at each call site. |

**Recommendation: C.** The defect is not that `io` is ungated — that part is correct. It is that
**the ungated path is what you get by not typing anything.** C fixes exactly that and leaves the
policy untouched. B fixes the wrong thing.

### Hole 2 — should crew evidence survive a fresh checkout?

| option | pros | cons |
|---|---|---|
| **A. Leave as-is, disclosed** | Zero risk; docstring is now honest about it. | The gate silently does nothing in the case it was built for. |
| **B. Un-gitignore `io/mementos/`** | Evidence travels; gate arms everywhere. | Every memento enters git history permanently. Contradicts this script's own `REQUIRED_IGNORES` guarantee. **Not recommended.** |
| **C. Arm from a committed, content-free marker** ⭐ | A tiny tracked file (e.g. `io/engagements/<date>-<id>.marker`) records *that* a crew ran without publishing *what* anyone wrote. Travels with the repo. Preserves the gitignore guarantee. | New concept; a marker nobody writes is a gate nobody arms — must be written by the spawn path, not by a rule. |
| **D. Fleet-wide retro index** | The correct long-term answer; also fixes the known per-repo over-fire. | Nobody has built one. Out of scope for a ruling today. |

**Recommendation: C, with the marker written by the spawn path rather than by any seat's discipline.**
This mirrors the mechanism that already works here: the MANDATE file's *existence* is the in-force
flag, and the spawn appends it. A marker written by a rule will be forgotten; a marker written by the
spawn cannot be. **If C is not ruled, A is the honest fallback. B should be declined regardless.**

### ⚠️ The two holes INTERACT — rule them together, not separately

Raised by Clayton (26770c97); measured by me before including it. The gate fires in **one of four
cells**:

| | `--slot root` | `--slot io` (the default) |
|---|---|---|
| **main repo** (crew records present) | **EXIT 6** ✅ the only cell that works | EXIT 0 — hole 1 |
| **fresh worktree** (records absent) | EXIT 0 — hole 2 | EXIT 0 — **both, independently** |

A worktree-isolated seat that also omits `--slot` is ungated **twice over, by two unrelated
mechanisms**. So:

- Closing **hole 1 alone** still leaves `worktree + root` at exit 0.
- Closing **hole 2 alone** still leaves `main + io` at exit 0.
- **The common case for a crewed engagement — an isolated seat taking the default slot — is the
  cell covered by neither fix.**

⇒ **Do not accept a fix for one hole as progress on the arming question.** Either ruling taken alone
produces a gate that looks repaired and still does nothing in the case it was built for. This is
also the one configuration nothing pins: the two `UNRULED_` tests pin each hole *separately*, and
no test pins the combination.

Two of my own results were wrong and were caught by the second seat, not by me. Both belong here,

to distrust:

1. **My first non-vacuity proof for the hole-2 test was garbage.** The test went red with

   corrected proof mutates the *fixture* so the record genuinely travels. The test is sound; my
   first evidence for it was not.
2. **I over-read a real measurement into a false class.** I measured that neither content floor was
   individually detectable and named the class "a redundancy that hides vacuity" — blaming the
   redundancy. Clayton built the falsifying config (`lines=4` plus two floor-isolating tests:
   control 28 passed, each mutation 1 red) and showed **the defect was a missing test, not the extra
   floor.** Corrected: *a redundancy makes a missing test invisible.* The remedy is a test isolating
   each member of the pair — buildable — rather than "avoid redundancy," which is not.

⇒ The generalizable form, and the reason both corrections are recorded rather than quietly fixed:
**a measurement does not license the conclusion drawn from it.** A real receipt is exactly what
makes an unmeasured generalization persuasive enough to be adopted.
