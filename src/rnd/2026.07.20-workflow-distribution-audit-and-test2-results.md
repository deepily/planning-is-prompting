## 3. Test 2 — scope precedence (RUN 2026-07-20)

**Method**: `claude -p "/probe-symlink"` executed headless from lupin's root, where BOTH fixtures exist — lupin-local `probe-symlink.md` (marker `PROJECT-LOCAL`) and user-scope symlink → PIP (marker `USER-SCOPE-SYMLINK`).

**Result, 2 of 2 runs**: `PROBE RESULT: USER-SCOPE-SYMLINK`.

**Verdict**: **user scope shadows project scope** — the inverse of the spec's §4.4 assumption. Consequences:

1. **The "free rollback" story is inverted.** A user-scope symlink takes effect everywhere IMMEDIATELY; local copies become inert while it exists. Rollback = `rm` the symlink (local copy resumes), not `git checkout`.
2. **Blanket symlinking of canonical commands is UNSAFE today**: canonical bodies hardcode `[PLAN]` prefix + PIP paths. Symlinked as-is, lupin's `/plan-session-end` would run with PIP's project config. The body/config split (Phases 1–2, `pip-config.md`) is a hard prerequisite, not a nicety.
3. **Intentional per-repo divergence gets silently shadowed** by any same-named user-scope install. The spec's `SHADOW` marker mechanism must move: divergence must be expressed as a repo-local file that user scope deliberately does NOT provide, or the divergence dies.

**Caveat on the instrument**: runs were headless (`-p`), not an interactive keystroke. Command discovery + content resolution through both scopes is the same code path; an interactive confirmation costs one keystroke if wanted.
