## The short version, and it corrects what I told you an hour ago

**Today, a manager does not self-re-spin — it succeeds itself.** It spawns a successor before its wall
and hands over. That is the timing rule in `workflow/manager-context-monitoring.md` §4c.

**But genuine self-re-spin is not a missing capability.** The mechanism to type into any session's
terminal already exists, runs in production every day, and is already used by a service that types
into panes it has no lineage relationship to. **I described this earlier tonight as "still worth
building." That undersold it — the hard part is built and shipped.**

⇒ **What is missing is one MCP verb**, not a mechanism.

## What already exists

### 1. The injector — `inject_qualifier_via_tmux()`

`lupin/src/lupin_cli/claude_code/hooks/lib/hook_common.py:992`

```python
subprocess.Popen(
    [ "bash", "-c",
      'sleep "$1" && tmux send-keys -t "$2" -l -- "$3" && sleep 0.25 && tmux send-keys -t "$2" Enter',
      "_", str( delay ), tmux_session, text ],
    start_new_session = True,
    stdout = subprocess.DEVNULL,
    stderr = subprocess.DEVNULL
)
```

It resolves a `session_id` to a tmux session through the session bridge, then types text into that
session's input as first-class user input and presses Enter.

**The property that makes self-re-spin possible is `start_new_session=True` combined with the leading
`sleep`.** The injecting process is **detached and outlives its caller**. It sleeps first, then types.
So a session can schedule an injection into its own pane and then stop existing in its current form —
the typing still happens.

That is exactly the shape self-clear needs, and it was not built for this.

### 2. The precedent — the arbiter already types into panes it does not own

`lupin/src/lupin_arbiter_app/arbiter_live_notify.py` → `make_tmux_push_fn`, with
`ArbiterConsumerJob._emit_dm` selecting it at runtime via the INI key `arbiter poke wake mechanism`
(default `"tmux"`). Full branch coverage in `src/tests/unit/test_arbiter_tmux_wake.py`; design at
`src/rnd/v0.1.8/2026.06.16-arbiter-tmux-wake-thread-cd-design.md`.

**This is a host-side service waking dormant sessions it never spawned, in production since
2026-06-16.** It degrades to `push_unavailable` rather than raising, falls back to a DM, and logs.

⇒ **The "lineage" objection dissolves here.** The reason `dismiss_sessions` cannot reap your own seat
is that it is scoped to sessions you spawned. **Typing into a pane has no such scoping** — it needs a
session id and a bridge entry, both of which a session has for itself.

### 3. The proof that identity survives — this session

**I am the receipt.** Session `9662b5ac` was `/clear`ed this morning and rehydrated as the same seat:
same session id, same tmux session, same persona (María 🌸), same repo, same board. The memento at the
repo root carried the state across. Twelve amendments of it are in `.claude-memento.md`.

**A `/clear` is not a new session.** It is the same seat with its context set to zero — which is
precisely why it preserves the thing a spawn-a-successor handoff cannot: **the persona keeps its own
name, so git log and history stay continuous.**

## What self-re-spin would actually be

Five steps, and only step 3 is new code:

1. **Reach a safe checkpoint.** No half-written files. Same precondition as any re-spin.
2. **Write the memento** to the repo root, with the board, the seats, and what a successor must do
   first. This already exists (`memento_io.py`) and is already the rehydrate contract.
3. **Schedule the injection at yourself** — `/clear`, into your own tmux session, after a delay long
   enough that the memento write has certainly landed.
4. **The detached process fires.** `/clear` is typed and submitted. Context → zero.
5. **SessionStart rehydrates** from the repo-root memento. Same seat, same persona, empty context.

```python
# The verb that does not exist yet, in the shape the existing injector already supports
self_respin( delay_seconds = 20, memento_path = "<repo>/.claude-memento.md" )
```

**Nothing about steps 1, 2, 4 or 5 is new.** Step 3 is `inject_qualifier_via_tmux( my_own_session_id,
"/clear", delay, wrap=False )` — with `wrap=False`, because the speakerphone voice rider must not be
applied to a slash command.

## The risks, stated honestly

These are the reasons to design it rather than paste it in tonight.

| risk | why it bites | mitigation |
|---|---|---|
| **Memento not yet written when the clear fires** | You clear into nothing and lose the session's state. The single worst outcome. | Verify the file on disk *before* scheduling, not after. Never schedule and then write. |
| **Session is mid-tool-call** | `send-keys` types into a busy input; the text may land in the wrong place or be swallowed. | Only fire from a turn boundary, and treat a failed clear as a no-op you can retry — never as done. |
| **Nobody can confirm it worked** | The session that fired it cannot report the outcome; it no longer holds the context that knew it was trying. | **This is the real design problem.** An external observer — the arbiter or a peer manager — should verify the seat came back and is at low context. |
| **Double-fire** | Two queued injections clear twice; the second lands on an already-fresh session and destroys the rehydrated context. | A one-shot marker file, checked by the injector, cleared at SessionStart. |
| **Irreversible** | There is no undo on a `/clear`. | Same class as the memento overwrite bug found this morning — treat it as destructive and guard it the same way. |

⚠️ **The third row is the one I would build first.** A manager that fires a self-clear and does not come
back is a silently dead seat, and the whole point of this policy is that seats do not die silently.

`workflow/manager-context-monitoring.md` §4 currently states the self-re-spin limit as a verified

**That last sentence is now wrong, and I wrote it.** There is a way; it is used in production daily;

agent-callable verb exposes it.**

⇒ The §4 table needs correcting, and §4c's closing subsection — the timing rule — stays true but
becomes a **fallback** rather than the only answer. **Succession is what you do while self-clear does
not exist. Self-clear removes the deadline entirely.**

I am not editing the policy on this yet. The claim deserves a working verb behind it before the
document promises one, and the last thing this policy needs is a tenth correction generated by me
writing ahead of the evidence.

## Why it is worth building

**Succession costs a whole manager's context to save a manager's context.** The successor boots empty,
reads a memento, re-derives what it can, and the outgoing manager's remaining budget is discarded.
Self-clear keeps the seat, the persona, the tmux session, the board, and the lineage — and costs one
memento write.

**And it removes a deadline from a tiring session's judgment.** The timing rule works if every manager
spawns its successor in time. Self-clear does not need anyone to have judged the moment correctly,
which matters most in exactly the condition it exists for.

## Recommendation

Build the verb, small, with the observer first:

1. **An external liveness check** for "seat cleared and came back" — arbiter-side or peer-manager-side.
2. **`self_respin()` as an MCP verb**, gated on a verified memento and a one-shot marker.
3. **Correct §4 of the policy** once the verb exists, and demote succession to the documented fallback.
