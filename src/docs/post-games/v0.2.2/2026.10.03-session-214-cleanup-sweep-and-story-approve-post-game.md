## 6. Lessons for the failure-mode catalog (if any)

One sighting each. Per the accumulate-before-graduating practice, none of these is a rule yet.

- **A batch control that does not list what it acts on.** Trigger: adding "do this to all N" beside an existing grouped list. Symptom: the operator cannot verify the batch from the control. Guard: a review question, "can the reader see every item this button touches, from where the button is?", and a browser test that asserts the rows are visible under the control before it is pressed.
- **Making the symptom unobservable and calling it fixed.** Trigger: a data change that makes a UI element stop rendering. Symptom: the report goes quiet, the cause is untouched, and a side effect appears somewhere else (here, rows filed under no epic). Guard: state what the fix changes about the cause in one sentence; if the sentence is about what is no longer displayed, it is not a fix.
- **An owner-only board query hides rows I manage.** Trigger: answering "what do I owe" with `owner_persona` alone. Symptom: a P0 owned by a peer and managed by me is missing. Guard: query both `owner_persona` and `accountable_manager` before saying the board is clear.
