## 6. Lessons for the failure-mode catalog (if any)

One sighting each unless noted. None is a rule yet.

- **A fake model in every test, and a full run as the first real call.** Trigger: a harness whose tests inject the model. Symptom: the run fails on the real reply shape after the review has passed. Guard: before a full run, one real call per model on an input with the real shape (here, a multi-point key). **Third sighting of the "friendly fake"**: the Session 213 retro records two (the stub importer's test double, and the Last Call stub of 2026-09-27) and names `workflow/testing-baseline.md` as the candidate home. Graduating it is the next step, as its own ticket, with the drafted rule taken back to a seat first.
- **A probe easier than the real input.** Trigger: checking a real dependency with made-up data. Symptom: the probe is clean and the real run is not. Guard: build the probe from the hardest property of the real input, and say which property that is.
- **A cache that hides how a value was produced.** Trigger: a flag that changes how a cached value is made. Symptom: a rerun with the flag off reuses values made with it on. Guard: Rio's practice, a second-ledger rerun whenever such a flag is added.
- **A brief that names a method instead of the outcome.** Trigger: "do it the way the sibling does". Symptom: the worker copies a shape that does not fit. Guard: state what must be true afterwards; offer the sibling as a place to look.
- **Checking the venue is not asking the peers.** Trigger: merging into a shared branch. Symptom: a peer's stacked merge lands on a moved base. Guard: ask "who has a merge in flight" as well as running the idle check.
